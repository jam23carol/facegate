# FaceGate — система распознавания лиц с голосовым приветствием и админ-панелью

Клиент-серверная система на Python: клиент захватывает видео с камеры и отправляет
кадры на сервер, сервер распознаёт лица (`face_recognition`/`dlib`), сравнивает их
с эталонами и возвращает команду приветствия вместе с **заранее синтезированным
аудио** «Здравствуйте, {Имя}!». Клиент мгновенно воспроизводит его через колонки.

Всё, что видит камера, в реальном времени показывается в браузере, в админ-панели
(`http://<адрес сервера>:8080`): живой видеопоток со всех камер, рамки и имена
распознанных лиц, статистика, журнал, управление людьми, озвучкой, звуками и настройками.

```
┌──────────────┐  кадры JPEG (PUSH→PULL :5555)   ┌────────────────────────────┐
│    Клиент    │ ──────────────────────────────► │          Сервер            │
│ камера +     │                                 │  headless, без GUI-окон    │
│ динамик      │ ◄────────────────────────────── │  распознавание лиц         │
└──────────────┘  greet/speak + WAV (SUB←PUB     │  Silero TTS (русский голос)│
                     :5556)                      │  админ-панель (Flask :8080)│
        ┌────────────┐                           └──────────────┬─────────────┘
        │  Браузер   │  MJPEG-видео, рамки, настройки, журнал,  │
        │ админка    │  саундборд, добавление лиц из кадра      │
        └────────────┘ ◄───────────────────────────────────────┘
                         http://<сервер>:8080
```

## Быстрый старт в Docker (рекомендуется)

Docker — основной сценарий: образ сервера уже содержит dlib (без компиляции),
Silero TTS с русской моделью и ffmpeg.

```bash
cp .env.example .env             # и отредактируйте пароли/пути под себя
docker compose up -d server      # сервер + админ-панель на :8080
docker compose logs -f server
```

Админ-панель: `http://localhost:8080`, вход **`admin` / `admin`** (панель сразу
предложит сменить пароль; свои значения — `ADMIN_USER`/`ADMIN_PASSWORD` в `.env`).

Клиент с камерой на этом же хосте:

```bash
docker compose --profile client up -d client
```

Данные живут в bind-томах рядом с compose-файлом: `known_faces/`, `voice_cache/`,
`admin_data/`, `debug_frames/`, `soundboard/`.

### Сеть докеров

* Сервисы общаются через **явную bridge-сеть `face-net`**: клиент подключается к
  серверу по имени сервиса (`SERVER_HOST=server`), никаких `network_mode: host`.
* Наружу публикуются только порты сервера: `${WEB_PORT}:8080` (панель),
  `${VIDEO_PORT}:5555` (приём видео), `${COMMAND_PORT}:5556` (команды). Они нужны
  лишь клиентам **с других машин**; если клиент один и он в этом же compose —
  публикацию 5555/5556 можно удалить.
* Имена/значения всех портов задаются в `.env` — конфликт `port is already
  allocated` лечится одной строкой `VIDEO_PORT=15555`.

### Подключение к стороннему серверу

Если сервер распознавания уже работает где-то ещё (другой хост, VPS, чужой
контур), локальный сервер поднимать не нужно — весь клиент настраивается в `.env`:

```ini
SERVER_HOST=192.168.1.50        # IP или домен стороннего сервера
SERVER_VIDEO_PORT=5555          # опубликованный на нём порт приёма видео
SERVER_COMMAND_PORT=5556        # опубликованный на нём порт команд
CAMERA_ID=auto                  # первая работающая камера (или индекс/путь)
PUID=1000                       # id -u
PGID=1000                       # id -g
```

```bash
docker compose --profile client up -d client    # поднимется ТОЛЬКО клиент
```

Клиент соединяется с сервером исходящими TCP-соединениями (PUSH → :5555,
SUB ← :5556) — на стороне сервера достаточно открыть эти два порта в firewall.
Без Docker тот же клиент — один файл: `SERVER_HOST=192.168.1.50 python client.py`.

### Камера и звук определяются автоматически

**Камера.** `CAMERA_ID=auto` (по умолчанию): клиент перебирает все
`/dev/video*` хоста и берёт **первый узел, который реально читает кадры** —
не важно, `video0` это или `video3`, и даже если половина узлов — служебные
(метаданные). В контейнер устройства попадают без перечисления конкретных
имён (compose не падает, если `/dev/video0` на хосте нет):

```yaml
device_cgroup_rules:
  - "c 81:* rmw"      # класс V4L2 — все /dev/video*
  - "c 116:* rmw"     # класс ALSA — все /dev/snd/*
volumes:
  - /dev:/dev
group_add:
  - "${VIDEO_GID:-video}"   # файловые права на /dev/video*
  - "${AUDIO_GID:-audio}"   # файловые права на /dev/snd/*
user: "${PUID:-1000}:${PGID:-1000}"
```

**Звук.** Плеер выбирается автоматически по окружению:

1. живой сокет PulseAudio/PipeWire (`PULSE_DIR`, проброшен в `/tmp/pulse`) → `paplay`;
2. иначе ALSA `/dev/snd` (проброшена через `/dev:/dev` + cgroup-правило) → `aplay`;
3. дальше по списку: `ffplay`, `play`, `mpv`;
4. явное переопределение — `AUDIO_PLAYER=...` в `.env`.


### Озвучка (TTS)

* **По умолчанию в Docker — `silero`**: нейросетевой Silero TTS (официальный
  пакет `silero`, модель `v5_ru`). Голоса: `aidar`, `baya`, `kseniya`, `eugene`,
  `xenia` (`TTS_VOICE=baya` в `.env`). Модель скачивается **при сборке образа** —
  в рантайме интернет не нужен, синтез живёт в отдельном процессе-воркере
  (~0.1 с на фразу после первой загрузки модели).
* Никакой «русской озвучки английским голосом»: silero — русская модель;
  запасной `espeak-ng` тоже вызывается с языком `ru` по умолчанию.
* Движок переключается на лету в панели: **Настройки → Озвучка → «Движок
  озвучки»** (`auto` / `silero` / `espeak` / `pyttsx3`), там же голос и скорость
  (`tts_speed` для silero, `tts_rate` слов/мин для espeak). Смена движка/голоса
  автоматически пересинтезирует кэш приветствий.
* Воркеру Silero нужно ~600 МБ ОЗУ. На слабых машинах (1–2 ГБ) выберите движок
  `espeak` — он почти не потребляет память.

## Админ-панель

Вкладки: **Камеры**, **Люди**, **Саундборд**, **Настройки**, **Журнал**.

### Камеры

* Живое видео с каждой камеры (MJPEG), рамки и имена лиц рисуются браузером
  поверх потока (координаты приходят JSON-ом — картинка плавная даже когда
  распознавание медленнее потока).
* Статус «в эфире / нет сигнала», FPS, разрешение, счётчики, хост и камера клиента.
* Кнопки: **на весь экран**, **снимок на сервер**, **скачать кадр**,
  **＋ лицо из кадра**, **объявить**, **убрать**.

### Добавление лица из текущего изображения

Два способа, оба — прямо из живого видео:

1. **На чипе любого обнаруженного лица** (особенно красного «неизвестный»)
   нажмите «**+**» → откроется диалог с крупным превью этого лица.
2. Кнопка «**＋ лицо из кадра**» в действиях камеры: сервер сам найдёт лица в
   последнем кадре; если лицо одно — сразу покажет превью, если несколько —
   предложит выбрать нужное миниатюрой.

В диалоге достаточно ввести имя → сервер вырежет лицо с запасом по краям,
проверит его, сохранит как эталон (`known_faces/Имя.jpg`) и поставит в очередь
синтез приветствия — **без перезапуска сервера**. Повторное добавление того же
имени добавляет ракурс (`Имя_2.jpg`) и повышает точность распознавания.

### Люди

* Имя + фото → «Добавить» (проверка: нет лица — отказ). Карточка человека:
  все фото (каждое удаляется отдельно), статус озвучки, текст фразы.
* Кнопки: **переозвучить**, **проверить привет**, **переименовать**, **удалить**.

### Саундборд

Библиотека всех записанных звуков системы:

* **загруженные файлы** (WAV/MP3/OGG/FLAC/M4A, до 25 МБ) — форма загрузки
  вкладки; каталог `soundboard/` подключён томом, файлы можно класть и напрямую;
* **синтезированная озвучка** — приветствия людей и объявления попадают сюда
  автоматически (по индексу `voice_cache/index.json`).

Каждый звук можно:

* ▶ **проиграть в браузере** (элемент `<audio>` прямо в карточке);
* 📢 **транслировать клиентам** — звук уходит командой `speak` на колонки
  одного или всех клиентов в эфире (не-WAV форматы конвертируются ffmpeg);
* **скрыть** — элемент пропадает из списка, но остаётся на диске; вернуть —
  галочка «показывать скрытые» → «показать»;
* **удалить**.

### Настройки

Применяются мгновенно и сохраняются в `admin_data/settings.json`:

| Параметр | По умолчанию | Смысл |
|---|---|---|
| Порог схожести | 0.6 | Меньше = строже (0.45–0.55 строго, 0.6–0.7 мягко) |
| Кулдаун приветствия | 30 с | Как часто здороваться с одним человеком |
| Модель поиска лиц | hog | `hog` — быстро на CPU, `cnn` — точнее, нужен GPU |
| Ширина кадра для анализа | 0 | 0 = весь кадр; 640–960 сильно ускоряет распознавание |
| Распознавание / приветствия | да | Выключатели режимов |
| **Фразы приветствия** | 3 фразы | Пул шаблонов (строка = фраза). Для каждой синтезируется свой WAV, при распознавании фраза выбирается случайно без повторов подряд. Смена пула запускает пересинтез |
| **Ждать озвучку объявления** | 6 с | Сколько панель ждёт синтез, чтобы отправить объявление одной командой со звуком (0 = отправить текст, звук придёт следом) |
| **Движок озвучки** | auto | `silero` (рекомендуется) / `espeak` / `pyttsx3` |
| **Голос TTS** | пусто (=baya/ru) | aidar, baya, kseniya, eugene, xenia |
| **Скорость silero** | 1.0 | 0.5–2.0 |
| Скорость espeak | авто | слов в минуту |
| Качество JPEG / FPS трансляции | 80 / 15 | Баланс картинки и нагрузки |
| «Нет сигнала» через | 8 с | Когда считать камеру отвалившейся (индикация в панели) |
| **Доступен для команд** | 30 с | Мягкий порог для объявлений/саундборда: короткая потеря кадров не даёт 409 |
| **Максимум видеопотоков** | 24 | Лимит одновременных MJPEG-потоков (защита воркеров панели) |

### Журнал

* События распознавания: приветствия, неизвестные лица, кулдауны, объявления,
  трансляции саундборда, добавления людей (в т.ч. из кадра), входы в панель.
* Лог сервера в реальном времени с фильтром по уровню, паузой и очисткой.

## Запуск без Docker

### Установка

Скрипты установки **всегда создают виртуальное окружение** `.venv` — на
Ubuntu 24.04+, Debian 12+ и новых Fedora системный Python закрыт PEP 668
(`error: externally-managed-environment`), поэтому venv обязателен.

```bash
./install.sh                 # Linux/macOS: venv + dlib-bin, при неудаче — сборка
./install.sh --tts           # + нейросетевая русская озвучка Silero (torch CPU)
./install.sh --client        # только клиент: opencv + pyzmq + numpy (без dlib)
./install.sh --venv myenv    # своё имя окружения
./install.sh --system        # без venv (ставить в системный Python)
PYTHON=python3.12 ./install.sh   # выбрать интерпретатор

install.bat                  # Windows: venv + dlib-bin (озвучка — SAPI5)
install.bat --client         # только клиент
install.bat --no-venv        # без venv
```

Системный запасной TTS в Linux: `sudo apt install espeak-ng` (+ `ffmpeg` — для
трансляции не-WAV звуков саундборда клиентам).

### Сервер и клиент

Скрипты запуска сами находят `.venv`, подхватывают `.env` и выставляют
ограничения потоков OpenMP/dlib:

```bash
./run-server.sh                                    # Linux/macOS → панель :8080
./run-server.sh --web-port 9000 --threshold 0.5    # любые аргументы server.py
./run-client.sh --server-ip <IP сервера>
./run-client.sh --check-audio                      # проверка звука
run-server.bat                                     # Windows → панель :8080
run-client.bat --server-ip <IP сервера>
run-client.bat --list-cameras
```

То же самое напрямую (окружение нужно активировать самостоятельно):

```bash
.venv/bin/python server.py --tts-engine silero --tts-voice xenia
.venv/bin/python server.py --greet-templates "Здравствуйте, {name}!
Приветствую вас, {name}!
Рад вас видеть, {name}!"
.venv/bin/python server.py --no-web               # только ZMQ, без панели

.venv/bin/python client.py --server-ip <IP> --no-debug    # headless (Raspberry Pi)
SERVER_HOST=<IP> .venv/bin/python client.py --no-debug    # конфигурация через env
```

Клиент играет аудио первым доступным плеером своей платформы и **ждёт** его
завершения (концовка фразы не обрезается):

* Windows: `winsound` → PowerShell `SoundPlayer` → `ffplay`/`mpv`/`vlc`;
* Linux: `paplay` → `pw-play` → `aplay` → `ffplay` → `mpv` → `play` → `mplayer` → `vlc`;
* macOS: `afplay` → `ffplay` → `mpv`.

Перед воспроизведением любой WAV приводится к 16 бит / моно / 48 кГц, поэтому
частота 24 кГц от Silero больше не звучит вдвое быстрее и не отклоняется ALSA.

## HTTP API админ-панели

Все endpoints, кроме `/login` и `/api/health`, требуют сессию входа; изменяющие
запросы — заголовок `X-CSRF-Token` (или поле `csrf_token` в форме).

| Метод и путь | Назначение |
|---|---|
| `GET /api/health` | Живость сервера (без авторизации, для healthcheck) |
| `GET /api/status` | Аптайм, счётчики (включая `greets_by_person` — приветствия по людям), клиенты, **`current_faces`** (лица в кадре прямо сейчас), настройки, сводка озвучки |
| `GET /api/cameras`, `GET /api/cameras/<id>` | Список камер / одна камера |

| `GET /stream/<id>` | **MJPEG-поток** (можно вставить `<img src>` куда угодно) |
| `GET /api/cameras/<id>/frame.jpg` | Текущий кадр с разметкой (`?download=1` — как вложение) |

| `GET /api/snapshots`, `GET /snapshots/<file>` | Список и просмотр снимков |
| `GET /api/cameras/<id>/faces` | **Лица в текущем кадре** (рамки, имя, превью). 503 `{"busy": true}`, если движок распознавания занят |

| `GET/POST /api/settings` | Прочитать / применить настройки (на лету) |
| `POST /api/throttle/reset` | Сбросить кулдауны |

## Проверка и тесты

```bash
python tools/check_env.py --ports --camera   # диагностика окружения, портов, камер
python tools/check_env.py --client --audio   # диагностика клиента и звука
python -m pytest                             # 332 теста
python tools/e2e_check.py --image known_faces/фото.jpg --check-web   # цикл без камеры
python tools/smoke_check.py                  # сквозной прогон реального сервера
python client.py --check-audio               # тестовый сигнал на машине клиента

# внутри контейнера:
docker compose exec server python tools/check_env.py
docker compose exec server pytest
docker compose exec server python tools/e2e_check.py --image known_faces/michael.jpg --check-web
```

Тесты не требуют ни dlib, ни TTS, ни камеры: `face_recognition` подменяется
заглушкой, озвучка — `DummyVoice`, протокол Silero-воркера проверяется на
фейковом воркере, а в интеграционных тестах сервер поднимается по-настоящему
(реальные ZMQ-сокеты и HTTP) с запретом любых вызовов `cv2.imshow`.

## Частые проблемы

| Симптом | Решение |
|---|---|
| Камера не открывается в контейнере (`can't open camera by index`) | `CAMERA_ID=auto` сам найдёт рабочий узел; проверьте, что он виден: `docker compose --profile client exec client python client.py --list-cameras`. Права: `PUID`/`PGID` в `.env` (`id -u`/`id -g`), `VIDEO_GID=video` (или GID числом: `getent group video`). На хосте пользователь должен состоять в `video`: `sudo usermod -aG video $USER`. В compose уже настроены `device_cgroup_rules`, `/dev:/dev`, `group_add` и `user:`. После изменения `.env`: `docker compose --profile client up -d --force-recreate client` |
| Озвучка «кракозябрами» / robotic | Проверьте в Настройки → Озвучка, что движок `silero` (в Docker он по умолчанию). Для espeak укажите голос `ru` |
| `Silero TTS недоступен` / процесс убит | Движку нужно ~600 МБ ОЗУ и пакеты `silero`, `torch`, `scipy`. На слабом железе переключитесь на `espeak`; вне Docker: `./install.sh --tts` |
| Первая озвучка готовится долго | Silero грузит модель при первом синтезе (~5–60 с, однократно), дальше ~0.1 с на фразу. В Docker модель уже в образе |
| Панель открывается, но видео чёрное / «нет сигнала» | Клиент не подключён или шлёт не туда: проверьте `SERVER_HOST`/порты в `.env`, логи клиента (`docker compose logs client`) и вкладку «Журнал» |
| Клиент в Docker не слышен | Звук выбирается автоматически: PulseAudio-сокет (`PULSE_DIR=/run/user/<ваш UID>/pulse` в `.env`) → paplay, иначе ALSA → aplay. Проверьте плееры: `docker compose --profile client exec client sh -c 'which paplay aplay'`. Принудительно: `AUDIO_PLAYER=...` |
| Сторонний сервер не принимает клиента | На сервере должны быть опубликованы и открыты в firewall порты 5555/5556; клиенту нужен только исходящий доступ к ним |
| `port is already allocated` при `docker compose up` | Поменяйте `WEB_PORT`/`VIDEO_PORT`/`COMMAND_PORT` в `.env` |
| Забыл пароль админ-панели | Остановите сервер, удалите `admin_data/admin_users.json`, запустите с `ADMIN_PASSWORD='новый'` |
| `Please install face_recognition_models…` (без Docker) | `pip install "face_recognition_models>=0.3.0"`, затем `pip install --no-deps "face_recognition>=1.3.0"` |
| Ошибка сборки dlib (`setuptools`) | `pip install --force-reinstall "setuptools<70"` и повторить; или быстрый путь `./install.sh --prebuilt` |
| Сохранённые файлы принадлежат root | Уже исправлено entrypoint'ом (chown в `${PUID}:${PGID}` при каждом старте). Убедитесь, что в `.env` заданы ваши `PUID`/`PGID`, и пересоздайте контейнер: `docker compose up -d --force-recreate server` |
| Вкладки панели не переключаются / страница «мёртвая» | Обновите код и **пересоберите образ** (`docker compose build server && docker compose up -d server`), затем жёсткая перезагрузка страницы в браузере (Ctrl+Shift+R) — старый JS мог закэшироваться |
| Приветствие приходит текстом, без аудио | Фраза ещё синтезируется — сервер досылает звук отдельной командой, как только WAV будет готов. Проверьте «Настройки → Озвучка»: если движок «не найден», поставьте Silero (`./install.sh --tts`) или `sudo apt install espeak-ng` |
| Звук играет вдвое быстрее / обрывается на середине | Обновите клиент до 2.3: он приводит WAV к 48 кГц и ждёт завершения плеера. Принудительно: `--audio-rate 44100` (если карта не умеет 48 кГц) и `--audio-dedupe 0` |
| «Не найден аудиоплеер» на Windows | В 2.3 звук играет встроенный `winsound` — внешние программы не нужны. Диагностика: `python client.py --check-audio` |
| Панель зависала после «＋ лицо из кадра» | Исправлено в 2.3 (глобальная блокировка инференса + эмбеддинг по рамке). Если видите 503 «Движок распознавания занят» — панель повторит запрос сама; порог ожидания: `FACEGATE_INFERENCE_TIMEOUT` |
| Фото/снимки не сохранялись на диск | Исправлено: запись через `imencode` + байты (кириллица в путях больше не мешает), имена файлов ASCII, ошибки прав видны в логе. В Docker проверьте `PUID`/`PGID` и `sudo chown -R $(id -u):$(id -g) known_faces debug_frames voice_cache` |
| `error: externally-managed-environment` при установке | Используйте `./install.sh` / `install.bat` — они всегда создают `.venv` (PEP 668) |
| Не-WAV звук саундборда не транслируется клиентам | Нужен ffmpeg на сервере (`sudo apt install ffmpeg`; в Docker уже есть). В браузере такие файлы проигрываются и без него |
